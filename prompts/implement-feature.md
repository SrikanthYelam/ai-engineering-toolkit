Implement this feature: {{input}}

Work in these phases and keep each concise:

1. **Understand** - Explore the relevant code and conventions. List assumptions and open questions; ask me only if an answer would change the design.
2. **Plan** - Propose the smallest design that satisfies the request: files to change, new types, and tests to add. Wait for my approval if the change is large or risky.
3. **Implement** - Make the changes in small steps, following existing conventions. Do not refactor unrelated code.
4. **Verify** - Add or update tests, then build and run the test suite. Fix failures at the cause.
5. **Review** - Re-read your diff as a reviewer would. Summarize what changed, what was verified, and any follow-ups or risks.
