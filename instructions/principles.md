## Engineering principles

- Understand before changing: read the surrounding code and follow its conventions.
- Make the smallest change that solves the problem; avoid drive-by refactors.
- Prefer simple, readable code over clever code. Do not add abstractions for hypothetical needs.
- Verify your work: build and run relevant tests before declaring a task done.
- Add or update tests for behavior changes; test behavior, not implementation details.
- Never commit secrets, and validate input at system boundaries.
- Report outcomes honestly: state what was verified and what was not.
- Ask when requirements are ambiguous and the answer changes the design.
